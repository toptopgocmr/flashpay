API de paiement e-commerce

Acceptez les paiements par wallet FlashPay sur votre site ou votre application, sans agent ni scan en boutique. Chaque paiement alimente le même solde, le même journal et le même circuit de retrait que vos encaissements QR / NFC.

1. Clés et environnements

Dans l'app marchand › Paiement en ligne, générez vos clés sandbox (tests, aucun débit réel) puis live (production, compte validé). La clé secrète sk_… ne s'utilise que côté serveur ; elle n'est affichée qu'une seule fois. Restriction IP optionnelle.

Authorization: Bearer sk_sandbox_xxxxxxxxxxxxxxxx

2. Créer un paiement

POST /api/v1/payment-intents
Idempotency-Key: commande-1042-essai-1   (obligatoire)
{
  "amount": 15000,
  "currency": "XAF",
  "order_reference": "CMD-1042",
  "description": "2 x T-shirt",
  "customer_phone": "242066123456",      (optionnel : notifie le client dans l'app)
  "return_url": "https://boutique.cg/merci",
  "cancel_url": "https://boutique.cg/panier"
}
→ 201 { "id": "pi_…", "status": "pending", "checkout_url": "https://…/checkout/pi_…", "qr_payload": "flashpay://intent?id=pi_…" }

Redirigez le client vers checkout_url (ou affichez le QR). Il confirme avec son PIN dans l'app FlashPay ou sur la page web (code SMS + PIN), puis revient sur return_url?payment_intent=pi_…&status=confirmed.

3. Autres endpoints

GET  /api/v1/payment-intents/{id}           statut : pending | confirmed | failed | expired | refunded | partially_refunded
POST /api/v1/payment-intents/{id}/confirm   { "customer_phone": "…" } → notifie le client ; sandbox : { "test_outcome": "succeeded" | "failed" }
POST /api/v1/payment-intents/{id}/cancel
POST /api/v1/refunds                        { "payment_intent": "pi_…", "amount": 5000, "reason": "…" }  (Idempotency-Key obligatoire)
GET  /api/v1/refunds/{id}

4. Webhooks signés

Événements : payment.succeeded, payment.failed, payment.expired, refund.completed. Nouvel essai automatique (1 min → 24 h) tant que votre serveur ne répond pas 2xx.

FlashPay-Signature: t=1790000000,v1=hex(HMAC_SHA256(whsec_…, "1790000000." + corps_brut))

// PHP
[$t, $v1] = sscanf($_SERVER['HTTP_FLASHPAY_SIGNATURE'], 't=%d,v1=%s');
$ok = hash_equals(hash_hmac('sha256', $t . '.' . file_get_contents('php://input'), $whsec), $v1)
      && abs(time() - $t) < 300;

5. Widget « Payer avec FlashPay »

<script src="https://VOTRE-DOMAINE-FLASHPAY/js/flashpay-checkout.js"></script>
<div data-flashpay-button data-create-url="/mon-serveur/creer-paiement-flashpay"></div>

Votre route data-create-url crée le paiement côté serveur (clé secrète) et renvoie le JSON du payment intent ; le widget redirige vers checkout_url.

6. Plugins

WooCommerce : module fourni dans integrations/woocommerce-flashpay. PrestaShop : à venir (même API).

Limites

120 requêtes / minute par clé. Erreurs : { "error": { "code": "…", "message": "…" } }.
